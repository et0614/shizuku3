# Shizuku3 設定ファイル(setting.ini)仕様

作成日: 2026-08-28(最終更新: 2026-08-30) / 状態: 現行実装準拠

書式はShizuku1を踏襲する(`KEY=value; コメント`)。以下が全項目と既定値。

```ini
;=== 実行制御 ==========================================
ACCELERATION_RATE=0;         起動時の加速度(実時間1秒あたりに進めるシミュレーション秒数。0=停止)
                             ;既定0: クライアントがAV301(AccelerationRate)へ書き込むと計算開始
TIME_STEP=1;                 計算時間刻み[sec](1～60。60超はエラー)
CONTROL_INTERVAL=300;        制御最小更新周期[sec](本体は制約しない。ラッパー・GUIが参照して強制する)

;--- エミュレーション期間: 代表日の例 ------------------
;夏・冬・中間期(春)の代表日。春は外気冷房(全熱交バイパス)の
;有効性を学べるよう、やや涼しめの時期に寄せている。
SIMULATION_START_DATE=2026/8/5;  計算開始日(YYYY/M/D) — 夏季代表日の例
;SIMULATION_START_DATE=2026/1/21; 冬季代表日の例
;SIMULATION_START_DATE=2026/4/16; 中間期(春)代表日の例(涼しめ・外気冷房向き)
SIMULATION_DAYS=1;           エミュレーション日数[day](学習用は1日を標準とする)
DATA_OUTPUT_TSPAN=1;         データ書き出し間隔[min]

;=== BACnet ============================================
LOCAL_ENDPOINT=127.0.0.1;    エミュレータのLocal Endpoint IP
DEVICE_ID=3000;              BACnetデバイスID
UDP_PORT=47809;              ユニキャスト専用UDPポート(ブロードキャストは共有ソケット47808で
                             ;受信する。クライアントは127.0.0.1:47809へ接続する)

;=== エネルギー評価 =====================================
SYSTEM_COP_COOLING=3.5;      冷却系システムCOP[-](コイル冷却熱量の電力換算用)
SYSTEM_COP_HEATING=0.85;     加熱系システムCOP[-](温水ボイラ効率相当)
PUMP_WTF=40;                 ポンプの熱搬送効率WTF[-](定格水量時の 定格能力/ポンプ電力。
                             ;ポンプ電力は熱交換量ではなく実水量に比例するため、
                             ;空調機停止中でも弁が開いていれば電力を消費する)

;=== 快適性評価 =========================================

                             ;人が少なければ環境が悪くても正当化されるのか、という
                             ;倫理的な問いを考えるきっかけとして用意したオプション

;=== 乱数系統1: 気象 ====================================
WEATHER_SEED=1;              気象乱数シード(RandomWeather)
WEATHER_LOCATION=Tokyo;      生成地点(Tokyo/Osaka/Fukuoka/Sapporo/Sendai/Naha)

;=== 乱数系統2: 執務者 ==================================
OCCUPANT_SEED=2;             執務者乱数シード(人数生成・出退勤・在離席のマルコフ挙動)
OCCUPANT_INDUSTRY=InformationAndCommunications; 業種(Construction/Manufacturing/Infrastructure/
                             ;InformationAndCommunications/TrafficOrPostalService/
                             ;WholesaleOrRetailing/FinanceOrInsurance/RealEstate)
                             ;執務者数は床面積と業種の在籍密度モデルから確率生成される
                             ;(シード依存。176.5m2・情報通信業で概ね20～30人)
OCCUPANT_SHEAT_GAIN=60;      1人あたり顕熱[W]
OCCUPANT_LHEAT_GAIN=55;      1人あたり潜熱[W]

;=== 乱数系統3: 冷温水温度(AR(1)過程) ===================
WATER_TEMP_SEED=3;           冷温水温度乱数シード
CHW_TEMP_MEAN=7.0;           冷水入口温度: 平均[℃]
CHW_TEMP_STDEV=1.0;          冷水入口温度: 標準偏差[K](0=変動なし)
CHW_TEMP_CORR_TIME=1800;     冷水入口温度: 相関時間[sec]
HW_TEMP_MEAN=44.0;           温水入口温度: 平均[℃]
HW_TEMP_STDEV=2.0;           温水入口温度: 標準偏差[K](0=変動なし)
HW_TEMP_CORR_TIME=1800;      温水入口温度: 相関時間[sec]

;=== AHUアクチュエータ ===================================

PLUG_HEAT_GAIN_PERSON=40;    機器発熱[W/人](在席時)

;=== コンソールログ ======================================

                             ;(RL学習時はfalse推奨: 毎秒200行規模の出力で計算が遅くなる)
```

## 補足

### 初期状態の項目がないことについて

初期室温・湿度は指定しない。開始日の前日をΔt=3,600 s・空調停止で
収束するまで繰り返す周期定常計算による**自然室温**を初期状態とする
([01_物理モデル諸元.md](01_物理モデル諸元.md) §7)。夏は高温・冬は低温から
1日が始まり、朝の立ち上げ運転が学習課題の一部になる。
収束判定(0.01 K)は本体内の定数とし、iniには出さない。

### 乱数と再現性

- 3系統のシードを固定すれば結果は完全に再現される(学生間の公平な比較、RLの学習安定性の前提)。
  助走計算も同一シードから連続生成するため、初期状態を含めて再現される。
- 難易度の階段の作り方:
  - 標準偏差を0に(冷温水)すれば入門課題向けに決定論性が増す
  - シードだけ変えれば「同じ統計的性質の別の1日」が得られる(汎化性能の確認、RLの評価エピソード)

### CONTROL_INTERVAL の位置づけ

エミュレータ本体は操作量書込みの間隔を強制しない(BACnet的に自然な挙動を保つ)。
本項目は「授業ルールとしての最小更新周期」であり、Pythonラッパー・GUIがこの値を読んで
ステップ実行の進行幅として使用する。厳密な公平性が必要になった場合は、
本体側で操作量反映を本周期のラッチとするオプションを追加検討する。

### COP既定値

`SYSTEM_COP_COOLING=3.5`(電動チラー+搬送ポンプ込み相当)、`SYSTEM_COP_HEATING=0.85`
(温水ボイラ効率相当)は仮置き。授業の意図(冷暖房の相対コスト感)に応じて調整する。
