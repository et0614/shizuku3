# Shizuku3 物理モデル諸元

作成日: 2026-08-28(最終更新: 同日) / 状態: 仕様検討版

Shizuku1(Shizuku_2025.01.08)の基準階(2–7F)南側系統ペリメータを踏襲する。
ゾーン・窓の構成はBuilding.cs原典(L418–426、L629–635)と照合済み。
「要確認」印の値は実装時に原典と再照合すること。

## 1. ゾーン(単一ゾーン・瞬時完全混合)

Shizuku1基準階の南側系統は、南面と西面を統合してペリメータ系統として扱っている。
これに従い、**SWP(西面)+SP1–SP4(南面)の5ゾーンを統合して1ゾーン**とする。
(インテリアゾーンSI1–SI4は含めない)

| 統合元ゾーン | 寸法 [m] | 床面積 [m²] | 方位 |
|---|---|---|---|
| n-SWP | 3.25×14 | 45.5 | 西面ペリメータ(奥行3.25 m) |
| n-SP1 | 9.75×4 | 39.0 | 南面ペリメータ(奥行4 m) |
| n-SP2 | 6.5×4 | 26.0 | 南面ペリメータ |
| n-SP3 | 10.0×4 | 40.0 | 南面ペリメータ |
| n-SP4 | 6.5×4 | 26.0 | 南面ペリメータ |
| **統合後** | 南面幅32.75、西面長14 | **176.5** | |

| 項目 | 値 |
|---|---|
| 天井高 | 2.7 m |
| 気積 | 476.6 m³(空気質量計算は1.2倍係数: Shizuku1踏襲) |
| 家具等熱容量 | 空気質量×1006×10 [J/K](Shizuku1踏襲、Building.cs L928) |
| 統合に伴う簡略化 | 統合元ゾーン間の内壁(間仕切)は消滅する。その熱容量は無視する |

### 境界条件

| 境界 | 扱い |
|---|---|
| 南面・西面 | 外壁+窓(外気・日射に暴露) |
| 北面(インテリア側)・東面 | 断熱内壁、室間気流なし(隣接空間は別系統で同一設定温度に維持されるとみなす) |
| 床・天井 | ループ壁(自室の天井と床が連続する基準階の標準的扱い)。Popolo3の`AddLoopWall`で処理 |

## 4. AHU(Shizuku1 南側ペリメータ担当機を踏襲)

原典照合済み: 基準階(2–6F)の`ahuNumber=2`が南側ペリメータ担当
(AirFlowNetwork.cs L191–194のコメントで確認)。定格配列のインデックスは
`5+ahuNumber=7`(AirHandlingUnit.cs L220–229、L237–239)。VAV設計風量
{1,851, 1,283, 855, 1,316, 855} CMHがSWP+SP1–SP4の床面積比と一致することからも整合。

| 項目 | 値 |
|---|---|
| 設計給気風量 | 5,790 CMH(1.61 m³/s) |
| 設計還気風量 | 5,473 CMH(1.52 m³/s) |
| 設計外気風量 | 870 CMH(給気の約15 %) |
| 冷却能力 | 27.1 kW(コイル入口 26.6 ℃DB / 19.3 ℃WB、冷水48.6 L/min) |
| 加熱能力 | 14.5 kW(コイル入口 20.6 ℃DB / 14.2 ℃WB、温水25.9 L/min) |
| コイル | クロスフィン型(Popolo3 `CrossFinHeatExchanger`)、設計面風速2.5 m/s |
| 冷水入口温度(設計) | 7 ℃ / 温水入口温度(設計) 44 ℃ → **実際は外乱モデル(§5)で変動** |
| 構成 | 押込形(混合→給気ファン→コイル→加湿器)。ファン発熱はコイル上流で加わる |
| 給気ファン | 遠心、定格静圧0.85 kPa、回転数比0.4–1.0(インバータ) |
| 還気ファン | 遠心、定格静圧0.65 kPa、回転数比0.4–1.0(給気ファンと同一信号で連動) |
| 全熱交換器 | ロータリー式、効率0.76、バイパス可(標準: バイパスOff=熱回収有効) |
| 加湿器 | 滴下浸透気化式、飽和効率0.90。On/Off制御(設定40 %RH±10 %)、暖房時のみ |
| 外気・還気ダンパ | レンジアビリティ30:1。標準開度固定(全開=設計外気量)。OA/RAダンパは連動 |
| 冷温水弁 | 二方弁、**イコールパーセント特性、レンジアビリティ50**、定差圧仮定(開度→流量が確定) |
| 検出器 | Shizuku1のセンサ・熱量計モデル(応答遅れ付き、AirHandlingUnit.cs L258–263)を踏襲。パラメータは実装時に転記 |

風量計算は回路網を**使わない**(VAVなし単一ダクトでは分岐間の圧力バランス計算が不要なため)。
給気風量はファン相似則(風量∝回転数比、消費電力∝回転数比³)、外気量は外気枝
(ダクト+ダンパ+全熱交の抵抗、Shizuku1の校正値を流用)の単枝抵抗計算による。
VAVユニットは設けない(単一ダクト・単一ゾーン)。

## 5. 外乱モデル(乱数3系統)

各系統は独立したシードを持つ(setting.ini)。分散パラメータを0にすれば決定論的になり、
難易度の階段(全固定→一部ランダム→全ランダム)を構成できる。

### 5.1 気象(系統1)

Popolo3 `RandomWeather`(VARモデルによる確率的気象生成。東京ほか対応地点から選択)。
乾球温度・絶対湿度・日射・夜間放射を生成し、計算刻みへ内挿する。

### 5.2 執務者(系統2)

§3のとおり。出退勤・昼休み・在離席のすべてが確率的。

### 5.3 冷温水入口温度(系統3)

熱源側の不安定さを表現するAR(1)(Ornstein–Uhlenbeck)過程。計算刻みΔtに対し

```
T_w(t+Δt) = μ + (T_w(t) − μ)·φ + σ·√(1−φ²)·N(0,1),   φ = exp(−Δt/τ)
```

| パラメータ | 冷水既定 | 温水既定 |
|---|---|---|
| 平均 μ | 7.0 ℃ | 44.0 ℃ |
| 標準偏差 σ | 1.0 K | 2.0 K |
| 相関時間 τ | 1,800 s | 1,800 s |

- Δtによらず統計的性質が不変(厳密離散化)であること
- 将来拡張: 負荷率と相関させるオプション(ピーク時に水温が悪化する「熱源の息切れ」)。
  setting.iniに係数を予約し、既定0(無効)とする

## 6. CO2

- Popolo3 `MultiZoneCO2Model`(単一ゾーン+外気)。後退Euler解法
- 外気CO2濃度: setting.ini指定(既定420 ppm)
- 発生: §3(在室人数×標準発生量)
- 評価基準: 建築物衛生法1,000 ppm

## 7. エミュレーション期間と初期化

### 期間

**既定1日**(setting.ini `SIMULATION_DAYS`で変更可)。学習用として1週間は長すぎるため。
夏・冬・中間期(春)の代表日を開始日として使い分ける(setting.iniにコメントで例示)。
春の代表日は、外気冷房(全熱交バイパス)の有効性を学べるよう**やや涼しめの時期**に寄せる。

### 初期化(自然室温からの開始)

1日エミュレーションを固定室温(26 ℃/22 ℃等)から始めるのは不自然なため、
**助走計算による自然室温**を初期状態とする。

1. **開始日の前日1日分**を対象に、Δt=3,600 s・**空調停止(自由室温)**・**内部発熱なし
   (前日は休日相当で無人と想定)**で助走計算を行う
2. この前日を**収束するまでひたすら繰り返す**(周期定常計算)。収束判定は
   反復間の期間末状態差 < 0.01 K(本体内の定数。発散防止の安全上限回数のみ実装で設ける)
3. 収束した期間末の状態を初期値とする
4. 気象・執務者の乱数系列は本計算と同一シードから連続して生成する(再現性の担保)

結果として、夏は高温・冬は低温の自然室温から1日が始まり、
**朝の立ち上げ(プルダウン/プルアップ)運転そのものが学習課題**になる。

## 8. 時間の扱い

| 項目 | 値 |
|---|---|
| 計算刻み Δt | setting.ini指定。**1–60秒、既定60秒**(60秒超は不可)。助走計算(§7)のみ3,600 s固定 |
| 制御最小更新周期 | 既定300秒。エミュレータ本体は制約せず、ラッパー側で強制(setting.iniの値を参照)。難易度ノブ |
| ステップ実行 | 一時停止時刻をBACnetで書き込み→加速度>0で進行→本体が指定時刻で正確に自停止 |
| 加速度 | BACnetポイント(0=停止)。上限は計算負荷の実測後に確定 |

計算刻みを制御更新周期より十分細かくとる理由: コイル・給気温度応答(時定数数十秒)の
動特性を保存し、制御更新の合間に応答が発展する様子を観察可能にするため。

## 9. 評価指標(KPI)

エミュレータ内で以下を積算し、BACnetで公開する。重み付け(総合スコア化)は授業側・ラッパー側の責務とする。

| KPI | 定義 |
|---|---|
| エネルギー | E = Q_cool/COP_c + Q_heat/COP_h + P_fan(給+還) の積算 [kWh]。COPはsetting.ini指定 |
| 快適性(単純) | 在室時PPDの時間積算 [%·h](PPDは PMV−バイアス で評価。バイアスはsetting.ini指定、既定0) |
| 快適性(人数重み) | 在室時PPD×在室人数の時間積算 [人·%·h] |
| 空気質 | 在室時にCO2>1,000 ppmとなった時間の積算 [h](超過量加重は将来検討) |

快適性は2種類を常時積算・公開し、採点にどちらを使うかはsetting.ini
(`PPD_OCCUPANT_WEIGHTED`)を参照してラッパーが選択する。
**在室人数重み付けは「人が少なければ環境が悪くても正当化されるのか」という
倫理的な問いを考えるきっかけとして用意する**(授業での討論素材)。

加湿器(気化式)の消費エネルギーは無視する。ポンプ動力は熱源側に含まれるとみなしCOPで代表する。
