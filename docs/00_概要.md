# Shizuku3 仕様書 — 概要と設計方針

作成日: 2026-08-28(最終更新: 同日) / 状態: 仕様検討版(コーディング未着手)

## 1. 目的

建築環境(設備)系の学生に空調制御(PID制御、および将来的に強化学習)を学ばせるための
建物・空調システムエミュレータ。制御ロジックを含まない物理モデルを提供し、
外部から制御信号を与える構成とする。

学習系列は以下の3段階を想定する。

1. **試行錯誤期**: 制御理論を教えず、自らの手で操作量を調整させる(人力制御→自作ロジック)
2. **PID期**: PIDを提示し、自分の試行に名前と体系を与える。チューニング手法を学ぶ
3. **強化学習期**: 第1段階の試行錯誤の自動化として強化学習を導入する

## 2. システム構成

```
[学生] ── GUI(スライダー・グラフ表示)
           │
        Pythonラッパー(簡易API / Gymnasium互換 env.reset()/env.step())
           │ BACnet/IP
        Shizuku3 エミュレータ本体(C# / Popolo3)
```

- エミュレータの公式インターフェースは **BACnetのみ**(多用途への発展性を確保)
- BACnet実装は **BACnet 4.0.0(System.IO.BACnet)+ PoEMServerの実装パターン**を踏襲する
  (`C:\git_repositories\poem\software\PoEMServer` 参照。Shizuku1/2の実装は踏襲しない)。
  ポイント仕様も一般的なBACnet慣習(AI/AO/MSV、priority array、Engineering Units、COV、
  ReinitializeDeviceサービス等)に従う → [03_BACnetポイント一覧.md](03_BACnetポイント一覧.md)
- 教育用の簡便さはPythonラッパー層で吸収(BACnetの概念は学生から隠蔽)
- ステップ実行: 「一時停止時刻」を書き込んでから加速度を上げると、本体が
  その時刻で正確に自停止する(Shizuku2と同方式)。制御→指定時間進行→停止→制御…の
  ループを決定論的に実現する

## 3. モデル化方針(確定事項)

| 項目 | 方針 |
|---|---|
| 対象範囲 | 中央熱源方式のAHU系統のみ(冷温水コイルより二次側)。熱源はモデル化しない |
| 建物 | Shizuku1基準階の**南側系統ペリメータ**(南面SP1–SP4+西面SWP。南面と西面を統合してペリメータ系統として扱う)を**単一ゾーン(瞬時完全混合)**に統合。計176.5 m² |
| ゾーン境界 | インテリア側(北)・東側・隣接階は断熱境界、室間気流なし。南面・西面は外皮 |
| 梁 | モデル化しない(梁部の面積は外壁一般部に吸収) |
| ブラインド | **なし**(計算高速化、温度変動が大きくなり課題として良くなる) |
| VAV | **なし**。操作量は冷温水弁とファン回転数(+外気ダンパ)に限定 |
| AHU仕様 | Shizuku1の南側ペリメータ担当AHU(基準階ahuNumber=2、原典照合済み)を踏襲: 給気5,790 CMH、外気870 CMH、冷却27.1 kW、加熱14.5 kW |
| 冷温水弁 | 二方弁、イコールパーセント特性、レンジアビリティ50、定差圧仮定 |
| 冷温水温度 | 熱源の代わりに**AR(1)過程(自己相関付き正規乱数)**で変動する境界条件。パラメータはsetting.iniで指定 |
| エネルギー評価 | コイル処理熱量を**システムCOP(setting.ini指定)で割り戻し**、ファン動力・ポンプ動力(定格能力/WTFを実水量比で按分。停止中でも弁が開けば計上)と合算 |
| CO2 | Popolo3のMultiZoneCO2Modelで計算。外気ダンパによる換気量制御を評価対象とする |
| 執務者 | 出退勤傾向+ランダム微動(Popolo3 OfficeWorkerのマルコフ在離席モデル)。人体は定数発熱(2ノードモデルは使わない) |
| 快適性評価 | ゾーン単位のPMV/PPD。**PMVバイアス**をsetting.iniで指定可(例: +0.2ならPMV=+0.2でPPD最小5%)。PPD積算は**在室人数重み付けのオプション**あり(「人が少なければ環境が悪くても正当化されるのか」という倫理的な問いのきっかけとする) |
| 気象 | Popolo3 RandomWeather(VARモデル・東京等)による確率的生成 |
| 乱数管理 | 気象・執務者・冷温水温度の**3系統を独立シード**で管理。分散パラメータが難易度ノブになる |
| エミュレーション期間 | **1日**(setting.iniで日数変更可)。夏・冬・中間期(春)の代表日をsetting.iniにコメントで例示。春は外気冷房(全熱交バイパス)の有効性を学べるようやや涼しめの時期とする |
| 初期化 | 固定温度ではなく**自然室温**から開始: 開始日の前日をΔt=3600 s・空調停止で収束するまで繰り返す周期定常計算を行い、収束状態を初期値とする(朝の立ち上げ運転自体が学習課題になる) |
| 計算刻み | **最大60秒、任意設定可**(既定60秒) |
| 制御更新周期 | 計算刻みとは分離。**既定300秒**をラッパー側で強制(粗い更新周期が高度な制御の価値を生む)。難易度ノブとして可変 |

## 4. 標準状態(段階的開示)

初学者は弁・ファン(・外気ダンパ)のみ操作すればよいよう、以下は「機能するが触らなくてよい」
標準値で初期化する。学習が進めば自由に操作できる。

| 機器 | 標準状態 |
|---|---|
| 全熱交換器 | バイパスOff(熱回収有効) |
| 加湿器 | 有効、設定40 %RH・ディファレンシャル±10 %(≒30–50 %でOn/Off)、暖房時のみ |
| 外気ダンパ | 開度固定(全開=設計外気量) |
| 冷暖モード | カレンダーによる自動切替(上書き可) |
